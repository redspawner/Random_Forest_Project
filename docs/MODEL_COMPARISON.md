# Model comparison: Random Forest, Logistic Regression, Gradient Boosting, XGBoost and others

The app has a **model switch at the top right** and a **Compare models** tab. Eight model types go through
exactly the same procedure as the original Random Forest:
- repeated stratified cross-validation (5 folds × 5 repeats; the same random splits for every model);
- the safety rule: POSITIVE only where **PPV ≥ 90 %** and NEGATIVE only where **NPV ≥ 90 %**, each **proven
  with a one-sided 95 % Clopper–Pearson lower bound** (at least 10 calls per side); everyone else is
  INCONCLUSIVE → lumbar puncture;
- nested cross-validation for an honest estimate;
- the same safeguards (CHECK DATA, NOT APPLICABLE, red flag, more than 50 % missing).

`tests/test_models.py` checks this for every model type. Reproduce the tables with
`python tools/benchmark_models.py --external 6000`.

## Current results (2026-11-20): realistic data, no Aβ42/Aβ40

What changed:
- Aβ42/Aβ40 are not measured in the Coimbra cohort, so they are no longer model variables. The models use 8
  variables: p-tau217, APOE ε4, clinical stage, eGFR, anaemia, triglycerides, hypertension, stroke.
- The default dataset is now generated by **version 2** of the synthetic generator (see
  `data/default_training/DATASET_CARD.md`). It uses:
  - real CHS covariates;
  - real Knight ADRC CSF amyloid data;
  - deliberately **non-linear** biology: a kidney-function threshold, p-tau217 rising sigmoidally with
    amyloid load, and an APOE dose effect that changes with age.

  The old generator was additive and log-linear, which favoured logistic regression.
- Two model types were added: **XGBoost** (CPU build) and **Spline Logistic Regression** (a GAM-like logistic
  regression whose effects can bend).

### The shipped models (600 grey-zone patients; independent check on 6,000 new synthetic patients)

| Model | AUC (CV) | AUC (6,000 new) | Certified POSITIVE / NEGATIVE threshold | LPs avoided | Net LPs avoided per 100 at pt = 0.10 |
|---|---|---|---|---|---|
| Random Forest | 0.801 | 0.775 | none / none | 0 % | −0.8 |
| Logistic Regression | 0.802 | 0.790 | none / none | 0 % | −1.5 |
| Spline Logistic Regression | 0.804 | 0.787 | none / none | 0 % | −0.2 |
| Gradient Boosting | 0.797 | 0.781 | none / none | 0 % | −0.2 |
| XGBoost | 0.800 | 0.784 | none / none | 0 % | −0.2 |
| Extra Trees | 0.805 | 0.790 | none / none | 0 % | 0.0 |
| Support Vector Machine | 0.798 | 0.777 | none / none | 0 % | −0.4 |
| Ensemble (RF + LR + GB) | 0.804 | 0.792 | none / none | 0 % | +0.8 |

p-tau217 alone inside the grey zone: AUC ≈ 0.78.

**No model can prove PPV ≥ 90 % or NPV ≥ 90 % with 95 % confidence**, so every grey-zone patient stays
INCONCLUSIVE. All models reach the same ceiling (AUC ≈ 0.80). The routine variables add only about 0.02 AUC
to p-tau217 alone. The limit comes from the information in the data, not from the algorithm: no paired AUC
difference with the Random Forest is significant.

The decision curves say the same thing. At the exchange rate that matches NPV 90 % (pt = 0.10: one missed
amyloid-positive patient counts as much as 9 unnecessary LPs), no model avoids a meaningful number of LPs
compared with "LP for everyone". A benefit only appears if one accepts a much worse trade-off
(pt ≥ 0.2, e.g. about 20 net LPs avoided per 100 at pt = 0.2).

### Settings sweep (does any setting do better?)

About 45 settings were tried, chosen by repeated-CV AUC on the 600 patients; the 6,000 independent patients
were used only as a check:
- **Random Forest:** leaf size 3/10/25, max_features sqrt/0.5;
- **Logistic Regression:** C = 0.05/0.5/5;
- **Spline LR:** C = 0.1/0.5/2, 3 or 5 knots;
- **Gradient Boosting:** learning rate 0.03/0.06, 3 or 6 leaves, leaf size 20/40;
- **XGBoost:** depth 2/3, learning rate 0.02/0.05, 200/400 trees, min_child_weight 5/15;
- **Extra Trees:** leaf size 3/10/25, max_features sqrt/0.5;
- **SVM:** C = 0.1/0.5/2.

**Every setting gave a CV AUC between 0.78 and 0.81.** Deeper or faster-learning boosting was slightly worse
(it over-fits). The shipped settings are the best or simplest equivalent ones: XGBoost depth 2, learning rate
0.02, 200 trees; Spline LR C = 0.1 with 3 knots; Extra Trees leaf 10. The Random Forest is unchanged.

### What would make the 90 % / 95 % rule reachable?

**More patients** (realistic data, no Aβ; LPs avoided on 6,000 independent patients):

| Grey-zone patients | Logistic Regression | XGBoost |
|---|---|---|
| 600 | 0 % | 0 % |
| 1,500 | 0 % | 0 % |
| 3,000 | 4 % (PPV 93 %) | 8 % (PPV 91 %, NPV 94 %) |
| 10,000 | 39 % (PPV 89.9 %, NPV 89.5 %) | 36 % (PPV 91.9 %, NPV 90.1 %) |

Even at 10,000 patients the true PPV/NPV land just around 90 %: the threshold is proven on the training
patients but sits right at the target.

**A more informative variable.** With plasma Aβ42/Aβ40 kept (same realistic data, 600 patients), the AUC
rises to about 0.83:
- the Random Forest, Extra Trees, SVM and Ensemble certified a POSITIVE threshold (8–11 % of patients
  resolved, true PPV 90–93 %);
- no model certified a NEGATIVE threshold.

Other candidates that carry amyloid-specific information include a cognitive score (MMSE/MoCA), MRI atrophy
ratings or amyloid PET history. Only add them if they are routinely available in Coimbra.

**A relaxed target** (decided in advance): with 85 %/85 % proven with 95 % confidence and 600 patients:
- XGBoost resolves about 19–25 % (NPV ≈ 0.89 on new patients);
- Logistic Regression about 4–7 %.

You chose to keep 90 %/90 %.

### Small cohorts

See [`SMALL_COHORTS.md`](SMALL_COHORTS.md): training-only augmentation with literature-based synthetic
patients. With a good prior, 100 real patients reach the score quality of about 600. The evidence for the
safety rule must still come from real patients.

## Interpretation

- **Logistic Regression is the best overall here.** It avoids about 59 % of grey-zone lumbar
  punctures against 38 % for the Random Forest (nested), a difference that is statistically clear,
  with no significant increase in wrong calls. On the independent patients it has the highest AUC
  and the best PPV/NPV balance.
- **Gradient Boosting is the most cautious.** It makes the fewest errors (19 per 1000, PPV 98 %),
  but it answers fewer patients (47 %).
- **Extra Trees and the Ensemble** avoid many LPs, but they make more wrong calls. Extra Trees has
  the lowest external PPV (91.9 %), still above 90 %.
- **The AUCs are all within about 0.02 of each other.** The large differences in LPs avoided come
  from how many patients end up in the zones where the 90 %/95 % rule is proven, not from the
  ranking. This is why the comparison page ranks models by LPs avoided and wrong calls, not by
  AUC.
- **Why Logistic Regression wins on this data, and a caution:** the synthetic generator builds the
  LP result from mostly additive, log-linear effects (log p-tau217, Aβ42/40 ratio, APOE, stage,
  eGFR). That favours a logistic model. Real data can contain interactions and non-linear effects
  that favour the tree models. **The ranking must be redone on the Coimbra cohort**: train every
  model type at once and use the Compare models tab.

## How the settings were chosen

Each candidate went through the full procedure, including nested validation. A few standard,
conservative settings were tried per model; the round-1 and round-2 results are below. The
selection favoured settings that keep the nested PPV and NPV above 90 %, not only the largest
share of LPs avoided. The final check on 6,000 independent patients was run once, after the
choice.

| Candidate | AUC | LPs avoided (nested) | Wrong | PPV / NPV (nested) |
|---|---|---|---|---|
| LR C = 0.1 / 0.2 / 0.5 / 2 (log) | 0.899–0.900 | 58–60 % | 19–22 | 97–98 % / 93–94 % |
| LR C = 0.5 without log | 0.899 | 58 % | 18 | 100 % / 93.6 % |
| GB lr 0.05, 150 rounds, 8 leaves | 0.880 | 23 % | 15 | 92 % / **88 %** |
| GB lr 0.05, 300 rounds, 8 leaves | 0.874 | 22 % | 14 | 95 % / **87 %** |
| **GB lr 0.03, 150 rounds, 4 leaves** (chosen) | 0.883 | 40 % | 17 | 94 % / 93 % |
| GB stumps (2 leaves) | 0.880–0.885 | 35–39 % | 15–18 | no POSITIVE calls |
| ET leaf 5, 50 % of variables | 0.888 | 54 % | 19 | 98 % / 93 % |
| **ET leaf 3, sqrt** (chosen) | 0.894 | 60 % | 22 | 97 % / 93 % |
| ET leaf 10, all variables | 0.878 | 33 % | 11 | 98 % / 93 % |
| **SVM C = 0.5** (chosen) / C = 2 | 0.881 / 0.874 | 53 % / 45 % | 19 / 20 | 98 % / 93 % · 95 % / 92 % |
| Ensemble LR + RF | 0.898 | 59 % | 23 | 97 % / 93 % |
| **Ensemble RF + LR + GB** (chosen) | 0.895 | 52 % | 22 | 98 % / 92 % |

Lessons from the tuning:

- **More flexible gradient boosting over-fits:** larger trees or more rounds pushed its nested NPV
  below 90 % (87–88 %). The threshold rule protects the training data, but an over-confident model
  can still miss the target on new patients. Small, slowly learning trees fixed this.
- **Logistic Regression is insensitive to its setting:** any C between 0.1 and 2 gives the same
  result.

## Limitations of this comparison

- Synthetic data only, from a generator that favours additive effects (see above).
- Choosing settings and then the best model on the same 600 patients is slightly optimistic. The
  independent test reduces this concern but uses the same generator.
- With few POSITIVE calls (Gradient Boosting), the PPV confidence interval is wide.
- The SVM and Logistic Regression replace missing values by the median plus a missing indicator.
  If values are missing for clinical reasons in the real cohort, this behaves differently from the
  tree models.

## Possible upgrades

- **SHAP explanations per patient**: which variables pushed this patient's score up or down. This
  needs the `shap` package.
- **Calibration of the final score** (isotonic or Platt), so the score can be read as a
  probability. Thresholds would not change, since they use only the order of the scores.
- **Decision-curve analysis** (net benefit), a standard figure for diagnostic models in TRIPOD+AI
  papers.
- **XGBoost / LightGBM**: usually similar to HistGradientBoosting on data of this size; they add
  dependencies to the portable bundle.
- Comparison with the **p-tau217/Aβ42 ratio with two cut-offs** as a simple non-ML benchmark.
